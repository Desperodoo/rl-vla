# GAP-1/2/3 修复前后数据对比分析报告

> 日期：2026-03-12（更新：使用真实 v1 数据替代模拟数据）
> v1 数据来源：`recorded_data/mix/` (82 episodes, 28,519 frames)
> v2 数据来源：`data/test_gap_fix/` (2 episodes, 307 frames, 227 active)
> 分析脚本：`scripts/analyze_gap_fix.py`

## 1. 背景

数据采集时 `get_last_action()` 记录的是 SDK 规划层输出（`get_plan_joint_pos()` → FK），而非遥操作者通过 `track_pose()` 发送给机械臂的真实目标位姿。本报告基于**真实 v1 数据**（82 episodes）和**真实 v2 数据**（2 episodes），量化两种记录方式的差异。

### 1.1 两种 action 记录方式

| | v1（旧） | v2（新） |
|---|---|---|
| **数据来源** | `get_plan_joint_pos()` → FK | backend `target_end_arm_pose` |
| **物理含义** | SDK 内部规划层的下一个插值点 | 遥操作者发出的控制命令（目标位姿） |
| **HDF5 action_dim** | 15D（joints[6]+gripper[1]+FK_pose[7]+gripper[1]） | 8D（target_pose[7]+gripper[1]） |

### 1.2 之前模拟分析的误区

之前的报告用**相邻帧差分**（`obs[t+1] - obs[t]`）模拟 v1 训练标签，得出"v1 幅度仅为 v2 的 1/10"的结论。这个模拟假设 `FK ≈ obs[t]`（即 FK 输出近似等于当前实际位姿），但真实数据表明这个假设**不成立**：

| 方法 | 位移幅度 mean | 旋转幅度 mean |
|------|---------------|---------------|
| 模拟 v1（相邻帧差分） | 1.79 mm | 0.26° |
| **真实 v1**（FK vs obs） | **16.04 mm** | **4.53°** |
| 真实 v2（target vs obs） | 18.06 mm | 4.78° |

**真实 v1 的 FK 输出并不等于当前实际位姿**，而是 SDK 规划层指向遥操作目标方向的中间插值点，因此幅度远大于帧间差分。

## 2. 核心发现

### 2.1 训练标签幅度对比（真实数据）

| 指标 | v1 真实 (82 ep, 28519 frm) | v2 真实 (2 ep, 227 active frm) | 倍数 |
|------|---------------------------|-------------------------------|------|
| **位移幅度 mean** | **16.04 mm** | **18.06 mm** | **1.13x** |
| 位移幅度 median | 10.73 mm | 18.77 mm | 1.75x |
| 位移幅度 P95 | 49.18 mm | 29.70 mm | 0.60x |
| 位移幅度 max | 97.82 mm | 33.22 mm | 0.34x |
| **旋转幅度 mean** | **4.53°** | **4.78°** | **1.06x** |
| 旋转幅度 median | 3.37° | 4.73° | 1.40x |
| 旋转幅度 P95 | 13.24° | 8.97° | 0.68x |
| 旋转幅度 max | 29.65° | 10.79° | 0.36x |

**关键发现：v1 和 v2 的训练标签幅度在均值上非常接近（1.13x），但分布特征截然不同。**

### 2.2 分布特征差异（核心问题）

| 指标 | v1 | v2 |
|------|-----|-----|
| 均值 (mm) | 16.04 | 18.06 |
| 标准差 (mm) | 15.49 | 7.59 |
| **变异系数 (CoV)** | **0.97** | **0.42** |
| P10 (mm) | 0.9 | 7.7 |
| P25 (mm) | 4.5 | 12.5 |
| P50 (mm) | 10.73 | 18.77 |
| P75 (mm) | 21.9 | 23.2 |
| P90 (mm) | 38.1 | 28.1 |

v1 的变异系数（0.97）是 v2（0.42）的 **2.3 倍**，说明 v1 训练标签的幅度极不稳定。

### 2.3 v1 标签质量问题

v1 的 FK 输出作为训练标签存在以下问题：

**1. 方向高度一致但幅度噪声大**

| FK 方向 vs 实际运动方向 | 数值 |
|------------------------|------|
| 余弦相似度 mean | 0.978 |
| 方向对齐率 (cos>0.5) | 99.9% |
| 方向反转率 (cos<-0.5) | 0.0% |

FK 的方向几乎总是正确的（指向遥操作目标），但幅度取决于 SDK 内部的插值策略和控制周期，是不可控的。

**2. 分布「长尾」严重**

```
v1 训练标签分布:
  < 1mm:  7.7%   ← 近似静止（idle 或 SDK 追上目标）
  < 2mm:  13.3%
  < 5mm:  27.6%
  < 10mm: 47.7%  ← 约半数帧幅度 < 10mm
  < 20mm: 70.6%
  < 30mm: 82.3%
  < 50mm: 95.3%
  > 50mm: 4.7%   ← 长尾：幅度异常大（SDK 大步插值）
```

v1 的 P95=49.18mm 远大于 v2 的 P95=29.70mm，说明 v1 存在异常大的幅度跳变。

**3. 各轴分布不均匀**

| 轴 | v1 |abs| mean (mm) | v1 std (mm) | v2 |abs| mean (mm) | v2 std (mm) |
|---|---|---|---|---|
| X | 4.78 | 7.32 | 9.05 | 11.18 |
| Y | 9.92 | 16.98 | 9.74 | 11.42 |
| Z | 8.23 | 12.24 | 9.09 | 11.15 |

v1 在 X 轴的幅度明显小于 Y/Z，且 Y 轴标准差极大（16.98mm），暗示 SDK 插值在不同轴上的行为不一致。v2 各轴分布更均匀。

### 2.4 v2 数据质量

v2 记录的 `target_end_arm_pose` 相对于实际位姿 `qpos_end` 的差异（即控制延迟）：

| 指标 | 位置 (mm) | 旋转 (°) |
|------|-----------|----------|
| Mean | 18.06 | 4.78 |
| Median | 18.77 | 4.73 |
| P95 | 29.70 | 8.97 |
| Max | 33.22 | 10.79 |

这个领先量是正常的控制延迟（SDK 需要 1-2 个控制周期追上目标），且分布稳定（CoV=0.42）。

### 2.5 Roundtrip 精度验证

v2 的 SE(3) roundtrip 精度（`apply(rel, obs) → target`）：

| 指标 | 误差 |
|------|------|
| Mean | 0.0000 mm |
| Max | 0.0000 mm |

数学一致性完美。v1 同样满足这个性质（因为 `compute_relative_pose_transform` 和 `apply_relative_transform` 是精确的 SE(3) 逆运算），但 v1 的 roundtrip 恢复的是 FK 位姿——一个物理含义不确定的中间插值点。

## 3. 影响分析

### 3.1 GAP-1：幅度问题的修正认识

之前基于模拟数据认为 v1 训练标签"幅度仅为 v2 的 1/10"，**这个结论需要修正**。真实数据显示：

- **幅度均值接近**（16mm vs 18mm），v1 并非"信号几乎丢失"
- **真正的问题是标签质量**：v1 训练标签的变异系数是 v2 的 2.3 倍，且存在长尾分布
- v1 的 FK 幅度在不同帧之间不可预测，因为它取决于 SDK 内部状态

### 3.2 v1 对策略学习的真实影响

1. **标签噪声大**：CoV=0.97 意味着标签幅度的标准差几乎等于均值，模型面对的是高噪声标签
2. **长尾问题**：4.7% 的帧有 >50mm 的异常大幅度，可能导致训练不稳定
3. **物理含义不明确**：FK 是 SDK 内部插值点，其物理含义（"下一步机械臂要去哪"）是模糊的——它既不是遥操作者的目标，也不是机械臂的最终位置
4. **与推理时语义不一致**：训练时学到的是 "obs → FK 插值点" 的映射，但推理时应用的是 "obs → 期望目标" 的映射

### 3.3 v2 的改善

1. **标签质量高**：CoV=0.42，分布稳定可预测
2. **无长尾**：max=33.2mm（vs v1 的 97.8mm），无异常大幅度
3. **物理含义明确**：target_pose 就是遥操作者发出的控制命令
4. **训练-推理一致**：训练学到 "obs → target" 映射，推理时直接应用同一映射

### 3.4 数据流对比图

```
v1 (旧):
  手柄 VR 信号
  → scale=0.4 缩放
  → target_end_arm_pose (遥操作目标)
  → track_pose() 发送给 SDK
  → SDK 规划层接收
  → get_plan_joint_pos() ← ❌ 数据采集在此截取
  → FK()
  → action = SDK 内部插值点
    ✓ 方向正确 (cos_sim=0.978)
    ✗ 幅度不稳定 (CoV=0.97)
    ✗ 物理含义模糊

v2 (新，修复后):
  手柄 VR 信号
  → scale=0.4 缩放
  → target_end_arm_pose (遥操作目标) ← ✅ 数据采集在此截取
  → action = 遥操作目标位姿
    ✓ 方向正确
    ✓ 幅度稳定 (CoV=0.42)
    ✓ 物理含义明确
```

## 4. GAP-2 Scale 语义对齐

| | 旧 | 新 |
|---|---|---|
| 遥操作 scale | 0.4（隐含在数据中） | 0.4（显式记录在 `teleop_scale` 字段） |
| 训练标签含义 | rel = obs → FK 插值点（SDK 中间状态） | rel = obs → 遥操作目标（已含 scale） |
| 推理 teleop_scale | 0.4（错误地再次缩放） | 1.0（固定，不重复缩放） |
| 推理调速参数 | 无 | `inference_speed_scale`（独立参数） |

## 5. GAP-3 旋转约定确认

| | 旧 | 新 |
|---|---|---|
| 后端旋转约定 | 左乘（世界坐标系） | 左乘（世界坐标系） |
| 训练标签计算 | `inv(T_obs) @ T_FK`（右乘） | `inv(T_obs) @ T_target`（右乘） |
| 约定冲突？ | 不明确（FK≠target，但方向大体正确） | **无冲突**（直接记录绝对位姿，SE(3) 逆自然吸收） |
| Roundtrip 误差 | 数学精确，但恢复的是 FK 位姿 | 0.0000 mm，恢复的是遥操作目标 |

## 6. 结论

| GAP | 影响量化（基于真实数据） | 状态 |
|-----|------------------------|------|
| **GAP-1** | 训练标签幅度均值接近（16mm vs 18mm），但 v1 **变异系数是 v2 的 2.3 倍**（0.97 vs 0.42），且存在长尾（P95=49mm vs 30mm）。**物理含义不明确**（SDK 插值点 vs 遥操作目标）。 | ✅ 已修复 |
| **GAP-2** | scale=0.4 在推理时被重复应用（实际缩放 0.4×0.4=0.16 倍） | ✅ 已修复 |
| **GAP-3** | 旋转约定差异通过记录绝对位姿自然解决，无需转换 | ✅ 已修复（无冲突） |

### 修正后的核心结论

**之前的结论**（基于模拟数据）："v1 训练标签幅度仅为 v2 的 1/10"——**不准确**。

**修正后的结论**（基于真实数据）：v1 和 v2 的训练标签在幅度均值上接近（16mm vs 18mm），**但 v1 的核心问题是标签质量**：

1. **高噪声**：变异系数 0.97（vs v2 的 0.42），标签幅度几乎"随机"
2. **长尾分布**：4.7% 的帧有 >50mm 的异常大标签，最大达 97.8mm
3. **物理语义不一致**：训练学到的是 "obs → SDK 插值点" 映射，推理时需要 "obs → 目标位姿" 映射
4. **Scale 双重应用**（GAP-2）：推理时 teleop_scale=0.4 在 v1 数据上再次缩放，导致实际执行幅度仅为训练标签的 0.4 倍

v2 修复后，训练标签有明确的物理含义（遥操作目标），分布稳定（CoV=0.42），且推理时 scale 语义正确（不重复缩放）。
