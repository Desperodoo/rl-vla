## 1. 这份文档是干什么的

这份文档的目标是让你在另一台设备上可以快速接手当前 `pi05` 主线工作，而不需要重新从头翻仓库。

这次交接覆盖三件事：

1. **另一台设备上训练**
2. **另一台设备上离线 eval**
3. **把微调后的 checkpoint 搬回当前设备做真机测试**

训练数据你已经自行搬运过去了，所以这份文档不再覆盖数据传输本身，而是聚焦：

- 仓库里现在的主线决策是什么
- 关键脚本和关键文档在哪
- 训练 / eval / 迁移时最容易踩的坑是什么
- checkpoint 到底该搬哪些目录，怎么搬最稳

---

## 2. 当前主线一句话结论

当前仓库里 `pi05` 的主线已经不是：

- `pi05_droid + absolute ee_pose`

而是：

- **`pi05_base / pi05_libero + ee_delta + ee_only state + LoRA first`**

具体落实到代码层，就是：

- 默认 action representation 已切到 `ee_delta_pose_gripper`
- 默认 state mode 已切到 `ee_only`
- 默认官方 checkpoint 已切到 `pi05_base`
- `pi05_libero` 作为同等级重要对照初始化
- `absolute_pose_gripper` 仅保留为 baseline / ablation

如果你在另一台设备上要继续做训练或 eval，请优先沿着这条主线走，不要再默认回到 `pi05_droid`。

## 4. 两台设备分别负责什么

### 4.1 另一台设备：训练 + 离线评估机

这台设备上建议负责：

- 拉最新仓库分支
- 准备 `pi05_base` / `pi05_libero` 官方 checkpoint
- 运行 CARM -> LeRobot dataset 导出
- 运行 LoRA / full finetune
- 运行离线 eval
- 打包并迁移最终 checkpoint 与必要元数据

### 4.2 当前设备：真机测试机

这台设备上建议负责：

- 拉同一分支的仓库代码
- 接收从训练机搬回来的 checkpoint
- 保留与训练机一致的 base checkpoint 目录结构
- 保留 tokenizer snapshot 或设置 `PI05_TOKENIZER_PATH`
- 在你自己的真机测试流程里加载 `base + adapter` 或 full-finetuned checkpoint

### 4.3 需要特别坦诚说明的一点

当前仓库里已经有：

- `pi05` 的数据 bridge
- `pi05` 的 LeRobot/OpenPI 训练链路
- `pi05` 的离线 eval 脚本

但是当前仓库里**还没有完全收口成一个“pi05 直接真机部署入口”**。

也就是说：

- 训练和离线 eval 链路现在是主线
- 真机测试阶段，仓库能稳定提供的是 **checkpoint、dataset contract、评估脚本、动作语义说明**
- 你自己的真机推理入口如果是另一个部署栈，务必让它遵守这里定义的 `ee_delta_pose_gripper` 语义

## 5. 另一台设备上的最小落地步骤

下面这一节按执行顺序写。

### 5.1 拉仓库

如果另一台机器还没有仓库：

```bash
git clone git@github.com:Desperodoo/rl-vla.git
cd rl-vla
git checkout maniskill
git pull origin maniskill
```

如果已经有仓库：

```bash
cd /path/to/rl-vla
git checkout maniskill
git pull origin maniskill
```

### 5.2 准备 Python 环境

至少需要这些依赖能力：

- `torch`
- `lerobot`
- `peft`
- `tyro`
- `numpy`
- `scipy`
- `h5py`

如果你打算用 launcher：

- `accelerate`
- `lerobot-train`

现在 `launch_pi05_full_train.py` 和 `probe_pi05_batch_scaling.py` 已经不再绑定旧机器的绝对路径，而是：

- 默认从 `PATH` 自动找 `accelerate`
- 默认从 `PATH` 自动找 `lerobot-train`

如果自动找不到，可以显式传：

- `--accelerate_bin /path/to/accelerate`
- `--lerobot_train_bin /path/to/lerobot-train`

### 5.3 准备官方 base checkpoint

建议在训练机和真机机都统一放在：

- `~/openpi/pi05_base_pytorch`
- `~/openpi/pi05_libero_pytorch`

这很重要，因为 LoRA adapter 的配置里通常会隐式依赖 base model path。跨机器如果路径乱掉，最容易在这里出问题。

推荐命令：

```bash
python -m rlft.offline.prepare_openpi_pi05_checkpoint --checkpoint_name pi05_base
python -m rlft.offline.prepare_openpi_pi05_checkpoint --checkpoint_name pi05_libero
```

现在默认 cache 目录已经改成：

- `~/.cache/openpi`

如果你要自定义，也可以传：

```bash
python -m rlft.offline.prepare_openpi_pi05_checkpoint \
  --checkpoint_name pi05_base \
  --cache_dir /your/cache/openpi \
  --output_dir /your/openpi/pi05_base_pytorch
```

### 5.4 导出主线数据集

主线建议先导出：

- `state_mode=ee_only`
- `action_representation=ee_delta_pose_gripper`

命令：

```bash
python -m rlft.offline.export_carm_to_lerobot \
  --demo_path /path/to/your/recorded_data \
  --output_dir /path/to/pi05_lerobot_export_delta \
  --state_mode ee_only \
  --action_representation ee_delta_pose_gripper
```

导出后一定会有：

- `meta/info.json`
- `data/.../*.parquet`
- `pi05_bridge_metadata.json`

这个 `pi05_bridge_metadata.json` 很关键，后面 offline eval 会把它的 `bridge_contract` 带进结果里。

### 5.5 主线训练

#### 路线 A：`pi05_base + ee_delta + LoRA`

```bash
python -m rlft.offline.train_pi05 \
  --demo_path /path/to/your/recorded_data \
  --auto_export_lerobot_dataset true \
  --export_output_dir /path/to/pi05_lerobot_export_delta \
  --state_mode ee_only \
  --action_representation ee_delta_pose_gripper \
  --official_openpi_checkpoint_name pi05_base \
  --policy_pretrained_path ~/openpi/pi05_base_pytorch \
  --use_peft true
```

#### 路线 B：`pi05_libero + ee_delta + LoRA`

```bash
python -m rlft.offline.train_pi05 \
  --demo_path /path/to/your/recorded_data \
  --auto_export_lerobot_dataset true \
  --export_output_dir /path/to/pi05_lerobot_export_delta \
  --state_mode ee_only \
  --action_representation ee_delta_pose_gripper \
  --official_openpi_checkpoint_name pi05_libero \
  --policy_pretrained_path ~/openpi/pi05_libero_pytorch \
  --use_peft true
```

#### baseline：`pi05_base + absolute_pose_gripper + LoRA`

```bash
python -m rlft.offline.train_pi05 \
  --demo_path /path/to/your/recorded_data \
  --auto_export_lerobot_dataset true \
  --export_output_dir /path/to/pi05_lerobot_export_abs \
  --state_mode ee_only \
  --action_representation absolute_pose_gripper \
  --official_openpi_checkpoint_name pi05_base \
  --policy_pretrained_path ~/openpi/pi05_base_pytorch \
  --use_peft true
```

### 5.6 多卡训练

如果你需要多卡训练，优先看：

- [../rlft/offline/launch_pi05_full_train.py](../rlft/offline/launch_pi05_full_train.py)

它会额外产出：

- `train.log`
- `resource_monitor.jsonl`
- `launch_command.sh`
- `launch_config.json`

这些文件后面做结果复盘和跨设备迁移时都很有用，建议一起保留。

## 6. 离线 eval 攻略

### 6.1 base-only eval

适用于：

- 官方 base checkpoint
- full finetune 产物本身就是完整 `pretrained_model` 目录

```bash
python -m rlft.offline.eval_pi05 \
  --dataset_root /path/to/pi05_lerobot_export_delta \
  --policy_pretrained_path ~/openpi/pi05_base_pytorch \
  --output_path /path/to/pi05_eval_base.json
```

### 6.2 LoRA eval

适用于：

- base checkpoint + LoRA adapter

```bash
python -m rlft.offline.eval_pi05 \
  --dataset_root /path/to/pi05_lerobot_export_delta \
  --policy_pretrained_path ~/openpi/pi05_base_pytorch \
  --peft_adapter_path /path/to/train_output/checkpoints/020000/pretrained_model \
  --output_path /path/to/pi05_eval_lora.json
```

### 6.3 tokenizer 路径注意事项

`eval_pi05.py` 现在不再写死到旧机器的 `/home/wjz/...` tokenizer snapshot。

它现在的规则是：

1. 如果传了 `--tokenizer_path_override`，就用这个路径
2. 否则读取环境变量 `PI05_TOKENIZER_PATH`
3. 如果两者都没有，就退回到 checkpoint 自己的配置

推荐做法是，在训练机、eval 机、真机机都统一设置：

```bash
export PI05_TOKENIZER_PATH=/path/to/local/paligemma_snapshot
```

这样最稳，不容易在换机时触发远程拉取或路径失效。

### 6.4 eval 结果里会自动带什么

现在 `eval_pi05.py` 会把 dataset 根目录下的：

- `pi05_bridge_metadata.json`

读出来，并把其中的：

- `bridge_contract`

写进结果 JSON。

所以你后面比较不同实验时，不用靠文件名猜动作语义。

## 7. checkpoint 导出与迁移攻略

这一节是这份交接里最重要的部分。

### 7.1 迁移时建议保留的产物清单

#### 训练机 -> 评估机 / 真机机，建议迁移这些目录

1. **官方 base checkpoint 目录**
   - 例如：`~/openpi/pi05_base_pytorch`
   - 或：`~/openpi/pi05_libero_pytorch`

2. **微调产物目录**
   - LoRA 常见形态：`.../checkpoints/<step>/pretrained_model`
   - full finetune 常见形态：同样是一个完整 `pretrained_model` 或完整模型目录

3. **导出的 LeRobot dataset 目录**
   - 至少离线 eval 机需要
   - 尤其要保住里面的 `pi05_bridge_metadata.json`

4. **训练 launcher 目录**
   - 例如：`...__launcher`
   - 里面有命令、日志、显存监控，后续回溯很值钱

### 7.2 LoRA 迁移的“最小可用”和“最稳妥”两档

#### 最小可用

至少带：

1. `pi05_base_pytorch` 或 `pi05_libero_pytorch`
2. `checkpoints/<step>/pretrained_model`

#### 最稳妥

建议带：

1. base checkpoint 目录
2. adapter 目录
3. 对应训练输出根目录
4. 对应 launcher 目录
5. 对应 dataset export 目录

这是我更推荐的方案，因为后面一旦出现：

- adapter 路径不匹配
- tokenizer 配置不一致
- base checkpoint 不知道是哪一版
- 结果文件找不到上下文

你都还能追溯。

### 7.3 Full finetune 迁移

如果后续你跑 full finetune，那么通常迁移策略更简单：

- 直接迁移那个完整的 fine-tuned `pretrained_model` 目录

但即便如此，我仍然建议保留：

- 原始官方 base checkpoint 目录
- launcher 目录
- 训练输出根目录

因为后面经常需要确认：

- 这是 full 还是 LoRA
- 这个 checkpoint 是从 `pi05_base` 还是 `pi05_libero` 起步

### 7.4 最推荐的目录标准化

为了避免跨机器路径错乱，建议两台机器都统一使用：

```text
~/openpi/pi05_base_pytorch
~/openpi/pi05_libero_pytorch
~/runs/pi05_...
~/datasets/pi05_...
```

尤其是 base checkpoint 路径，尽量两台机器保持一致。

### 7.5 打包与搬运命令示例

#### 方式 A：`tar`

```bash
tar -czf pi05_base_pytorch.tar.gz -C ~/openpi pi05_base_pytorch
tar -czf pi05_libero_pytorch.tar.gz -C ~/openpi pi05_libero_pytorch
tar -czf pi05_lora_step020000.tar.gz -C /path/to/train_output/checkpoints/020000 pretrained_model
tar -czf pi05_export_delta.tar.gz -C /path/to parent_of_export_dir
```

#### 方式 B：`rsync`

```bash
rsync -avP ~/openpi/pi05_base_pytorch user@target:/home/user/openpi/
rsync -avP /path/to/train_output/checkpoints/020000/pretrained_model user@target:/home/user/pi05_ckpts/
rsync -avP /path/to/pi05_lerobot_export_delta user@target:/home/user/pi05_datasets/
rsync -avP /path/to/train_output__launcher user@target:/home/user/pi05_logs/
```

### 7.6 迁移后如何自检

在目标机器上至少做这几个检查：

1. base checkpoint 目录里是否有：
   - `config.json`
   - `model.safetensors`

2. LoRA adapter 目录里是否有：
   - `adapter_config.json`
   - `adapter_model.safetensors` 或等价 adapter 权重文件

3. dataset 目录里是否有：
   - `meta/info.json`
   - `data/.../*.parquet`
   - `pi05_bridge_metadata.json`

4. eval 是否能成功读取：
   - `--policy_pretrained_path`
   - `--peft_adapter_path`
   - `PI05_TOKENIZER_PATH`

## 8. 真机测试机上的建议做法

### 8.1 最稳的做法

把下面这些全部搬回来：

1. `~/openpi/pi05_base_pytorch` 或 `~/openpi/pi05_libero_pytorch`
2. 你要测试的 fine-tuned adapter / checkpoint 目录
3. 对应实验的离线 eval 结果 JSON
4. 对应实验的 `pi05_bridge_metadata.json`

这样你在真机侧至少能明确知道：

- 这个 checkpoint 对应的是哪种 action contract
- 对应的是 `base` 还是 `libero`
- 离线指标大概是多少

### 8.2 真机前最后做一次离线 sanity check

在真机机上重新跑一次：

```bash
python -m rlft.offline.eval_pi05 \
  --dataset_root /path/to/pi05_lerobot_export_delta \
  --policy_pretrained_path ~/openpi/pi05_base_pytorch \
  --peft_adapter_path /path/to/pretrained_model \
  --output_path /tmp/pi05_eval_sanity.json
```

如果这一步都不通，就不要直接上真机。

### 8.3 关于真机入口的现实说明

当前仓库里，`pi05` 训练和离线 eval 主线已经明确，但真机入口还没有完全收口成一个标准 `pi05` deploy entrypoint。

因此真机测试时，你需要自己确认：

- 你使用的推理入口是否支持 `pi05`
- 它是否按 `ee_delta_pose_gripper` 理解动作
- 它的 gripper 语义是否和训练时一致

如果这三件事不确认，checkpoint 搬回当前机器也不代表能直接安全执行。

## 9. 这次交接里最容易踩的坑

### 9.1 不要依赖旧机器绝对路径

当前代码里已经尽量做了可迁移处理，但你仍然应该优先显式传：

- `--policy_pretrained_path`
- `--accelerate_bin`
- `--lerobot_train_bin`
- `--tokenizer_path_override`

而不是赌默认值恰好匹配目标机器。

### 9.2 LoRA 不能只带一个零散文件

LoRA 最容易犯的错误是：

- 只拷一个 `adapter_model.safetensors`

正确做法是至少带整个 adapter 目录，因为通常还需要：

- `adapter_config.json`
- 其他 processor / config 信息

### 9.3 base checkpoint 路径最好标准化

这件事很重要，我再强调一次：

- 两台机器尽量都把官方 checkpoint 放在同样的目录层级

推荐：

- `~/openpi/pi05_base_pytorch`
- `~/openpi/pi05_libero_pytorch`

### 9.4 dataset export 也要保留

离线 eval 不只是要模型，还要 dataset。

尤其是：

- `pi05_bridge_metadata.json`

现在会直接写进 eval 结果，后续对照实验很有用。

## 10. 这一轮交接后，你最建议先做什么

如果你换到另一台设备后只做三件事，我建议按这个顺序：

1. 拉 `maniskill` 分支最新代码，并在目标环境里确认：
   - `python -m rlft.offline.prepare_openpi_pi05_checkpoint --help`
   - `python -m rlft.offline.train_pi05 --help`
   - `python -m rlft.offline.eval_pi05 --help`

2. 准备：
   - `pi05_base`
   - `pi05_libero`
   - `PI05_TOKENIZER_PATH`

3. 跑三条最小实验矩阵：
   - `pi05_base + ee_delta + LoRA`
   - `pi05_libero + ee_delta + LoRA`
