## 3. Go/No-Go 判定

**判定标准**: B 组 success_once > A 组 success_once + 3%

| 数据规模 | A | B | B - A | > 3%? | **判定** |
|---------|---|---|-------|-------|---------|
| 100d | 0.10 | 0.34 | **+0.24** | ✅ | **🟢 Go** |
| 669d | 0.54 | 0.48 | -0.06 | ❌ | **🔴 No-Go** |

### 综合判定: **🟡 条件性 Go**

- **小数据场景 (≤100 demos)**: D_syn+ 效果极为显著，13 条合成数据带来 +240% 的相对提升
- **大数据场景 (669 demos)**: D_syn+ 被大规模 demo 数据稀释，13 条贡献 < 2% 占比，甚至有轻微衰退
- **结论**: D_syn+ 的价值在数据稀缺场景下最具杠杆效应，随着 demo 数量增长边际递减明显

## 4. D_syn+ "等价 demo 数" 计算

### 4.1 BC Scaling Curve 参考数据 (20K 步)

| Demo 数量 | success_once |
|-----------|-------------|
| 25 | 0.02 |
| 50 | 0.04 |
| 100 | 0.10 |
| 200 | 0.16 |
| 400 | 0.32 |
| 669 | 0.40 |

### 4.2 等价计算方法

由于 B 组小数据实验在 100K 步下达到 success_once=0.34，我们用 scaling curve 反推达到该性能所需的纯 demo 数量。

**关键观察**: 100d@20K = 0.10, 100d@100K = 0.10 → 说明 100 demos 在 20K 步已饱和，更多步数无额外收益。因此可以用 20K scaling curve 近似插值。

**线性插值**:
- 400d → 0.32, 669d → 0.40
- success_once = 0.34 对应:
  $N_{eq} = 400 + \frac{0.34 - 0.32}{0.40 - 0.32} \times (669 - 400) = 400 + 0.25 \times 269 \approx 467$

**等价 demo 增量**:
$$\Delta N = 467 - 100 = 367 \text{ demos}$$

**每条 D_syn+ 等价 demo 数**:
$$\text{equiv\_per\_syn} = \frac{367}{13} \approx 28.2 \text{ demos/D\_syn+ traj}$$

### 4.3 等价分析总结

| 指标 | 值 |
|------|-----|
| 13 条 D_syn+ 等价总 demo 数 | **~367 demos** |
| 每条 D_syn+ 等价 demo 数 | **~28 demos** |
| 杠杆倍数 | **28× (1 条合成 ≈ 28 条人类演示)** |
| 适用场景 | 中小规模数据 (≤200 demos) |

> **注意**: 此等价数仅在小数据体制下成立。大数据场景 (669d) 中 D_syn+ 的边际贡献可能为零甚至负值。

### 4.4 为什么大数据场景退化?

1. **信噪比稀释**: 13/682 = 1.9% 的占比太低, 合成数据噪声可能被放大
2. **质量差距**: D_syn+ 的 p_yes 在 0.4~0.53 间, 远低于真实 demo 的 p_yes~1.0, 引入分布偏移
3. **冗余性**: 669 条 demo 已充分覆盖任务分布, 合成数据无法提供新信息
4. **训练动态**: 100K 步中, 少量低质量数据可能干扰后期精调

1. **Scaling curve 近似线性 (对数尺度)**: 从 25d 到 669d, success_once 从 0.02 上升至 0.40 (20K) / 0.54 (100K)

## 6. 结论与下一步建议

### 6.1 核心结论

| # | 结论 |
|---|------|
| C1 | **D_syn+ 在小数据场景价值巨大**: 13 条合成正例将 100d 的 success_once 从 0.10 提升至 0.34 (+240%), 1 条 D_syn+ ≈ 28 条人类演示 |
| C2 | **D_syn+ 在大数据场景无益甚至有害**: 669d 场景下 B 组反而衰退 6%, 合成数据被稀释且引入噪声 |
| C3 | **数据飞轮的杠杆效应高度依赖数据规模**: 存在一个临界点 (~200-300d), 超过后 D_syn+ 边际收益归零 |
| C4 | **D_syn+ 产出率是关键瓶颈**: 400 条 imagination 仅产出 13 条 D_syn+ (3.25% 通过率), 提升 WM 质量或降低 α 阈值是优先方向 |
| C5 | **success_at_end 同步改善**: 小数据下从 0.02→0.10, 说明 D_syn+ 不仅提升了"曾经成功"率, 也改善了终态控制质量 |

### 6.2 下一步建议

| 优先级 | 建议 | 预期效果 |
|--------|------|---------|
| **P0** | **提高 D_syn+ 产出率**: 降低 α 从 0.4 到 0.3, 或改善 WM 质量 (ADR-024 TIMING 修正) | 产出 30-50 条 D_syn+ → 进一步放大飞轮效应 |
| **P1** | **中等规模验证**: 200d + D_syn+ 实验, 确认 D_syn+ 拐点位置 | 验证 C3 假说 |
| **P2** | **加权采样**: 对 D_syn+ 适用更高采样权重 (如 3-5×), 防止大数据场景稀释 | 缓解 C2 的稀释问题 |
| **P3** | **迭代式飞轮**: 用 Iter-1 策略生成更多 D_real → 再 imagination → 更多 D_syn+ | 指数增长数据量 |
| **P4** | **质量过滤增强**: 用 ensemble VLM 或更严格的多帧一致性检查提升 D_syn+ 质量 | 减少分布偏移 |

### 6.3 对 VLAW 全流程的启示

- **数据飞轮在资源受限时最有价值**: 最适合作为冷启动 (cold-start) 策略, 用少量 WM+VLM 投入快速提升基线策略
- **大规模部署时应结合加权采样**: 避免合成数据污染高质量 demo 集
- **WM 质量是飞轮效率的根本决定因素**: 当前 3.25% 的 D_syn+ 产出率严重限制了飞轮规模, ADR-024 TIMING 修正完成后预期可显著改善
